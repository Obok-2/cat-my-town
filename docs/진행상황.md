## 저장소

- GitHub: https://github.com/Obok-2/cat-my-town (기본 브랜치 `main`, 작업 브랜치 `develop`)

## 폴더 구조

```
app/     React Native(Expo, JS) 앱
server/  Spring Boot 3.5 + MyBatis 백엔드
web/     홍보 사이트 · 관리자 웹 (React + Vite, JS)
infra/   Docker Compose (PostgreSQL + pgvector, MinIO, 서버 컨테이너, 웹 Nginx)
design/  화면 목업 (PDF + HTML 캔버스, 최신은 `우리동네고양이 UIUX 목업/`)
산출물/  DB 스키마(schema.sql), 앱·관리자 REST API 인터페이스 정의서 (ERD는 ERDCloud)
docs/    이 문서, README용 이미지(`docs/images/`)
```

## app/ 현재 상태

- 화면: 스플래시·로그인·카메라·매칭결과·이름짓기·목격 기록 작성·완료·도감·고양이상세·레벨·프로필.
- 로그인: Google ID Token을 서버가 검증한 뒤 자체 JWT(7일)를 발급하고 앱은 SecureStore에 보관한다.
  Google 네이티브 로그인 모듈은 실제로 로그인할 때만 불러온다(Expo Go에서는 Google 로그인 불가, Development Build 필요).
- 촬영: 탭이 열리면 카메라 → 위치 순서로 권한을 묻고, 셔터를 누를 때 위치 권한을 다시 확인한다.
  위치 권한이 없거나 위치를 못 잡으면 촬영 흐름을 진행하지 않아 모든 목격 기록에 좌표가 저장된다(웹은 위치 없이 진행).
  사진은 긴 변 1280px·JPEG 0.82로 줄여 `/app/camera/analyze`에 보낸다.
- 매칭 결과: `NOT_CAT`·`NEW_CAT`·`EXISTING_CAT`. 서버가 일치율 40% 이상 후보를 최대 3마리 내려준다.
- 도감·고양이 상세·레벨·프로필은 모두 서버 API로 조회한다. 레벨 5단계(`src/data/levels.js`): 1·5·12·16·30마리.
- 고양이 상세 지도는 카카오 지도 JS SDK(`KakaoMapView.js`/`.web.js`/`kakaoMapDraw.js`). 키·설정은 `AGENTS.md`「지도」 참고.
- 서버 호출은 `src/api/`의 기능별 모듈(axios + async/await). 서버 주소는 Git 제외 `app/.env`의 `EXPO_PUBLIC_API_URL`.
- 남은 목데이터: `src/data/store.js`·`seed.json`·`mockMatch.js`는 더 이상 화면에서 쓰지 않는다(정리 대상).

## server/ 현재 상태

- Spring Boot 3.5, JDK 17. 코딩 규칙·URL 체계는 `AGENTS.md`「코딩 규칙 (Java)」 참고.
- 앱 API(`/app/**`, 앱 토큰 `role=USER`):
  `/app/auth/{google,me}`, `/app/collection/{count,cats}`, `/app/level/count`, `/app/cat/{detail,markers,sightings,register,sighting}`,
  `/app/camera/{week-count,analyze}`, `/app/photo`.
- 관리자 API(`/admin/**`, 관리자 토큰 `role=ADMIN`): `/admin/auth/login`(admin_users + BCrypt), `/admin/dashboard`.
  명세는 `산출물/관리자_API_인터페이스_정의서.md`. 앱 토큰과 관리자 토큰은 서로 호환되지 않는다(403).
- 촬영 분석: DJL ResNet-18로 고양이 판별 → Voyage AI 임베딩 → pgvector로 사용자 본인 고양이 중 후보 검색
  (고양이별 유사도 상위 2개 평균, 보정 후 40% 이상). 임베딩은 `analysisId`로 서버 메모리에 30분 보관해 등록 때 재사용한다.
- 사진은 MinIO에 저장하고, 조회 API의 `photoUrl`은 `/app/photo?catId=`·`?sightingId=` 형태의 완전한 URL이다.
- 로그인 시 이름 대신 Google 이메일을 `users.display_name`에, 로그인 시각을 `users.last_login_at`에 저장한다.
- 레벨 기준은 `common.LevelPolicy` 한 곳에서 관리한다(`users.level` 캐시는 갱신하지 않음).
- CORS는 `WebConfig`에서 로컬 개발 주소와 관리자 웹 도메인을 허용한다.
- 비밀값(DB·MinIO·Voyage·JWT)은 배포용 `application.properties`에 로컬에서만 넣고 커밋하지 않는다.

## web/ 현재 상태

- `/`: 앱 홍보 원페이지, `/privacy`: 개인정보 처리 안내, `/admin`: 관리자 로그인·대시보드.
- 관리자 로그인·대시보드는 서버 API에 연결됨(`src/api/adminApi.js`, `web/.env`의 `VITE_API_URL=/api`).
  대시보드: KPI 4개·최근 7일 차트·레벨 분포·최근 로그인(이메일 가림). 나머지 메뉴는 "작업 중" 자리표시자.
- 로컬 개발(`npm run dev`)은 `vite.config.js` 프록시가 `/api`를 백엔드로 넘긴다(대상 주소는 `web/.env`의 `API_PROXY_TARGET`).

## 배포 현재 상태

- 웹 서버(AWS Lightsail): nginx가 홍보·관리자 웹 정적 파일을 서비스하고, `location /api/`로 백엔드에 프록시한다
  (SPA fallback, 업로드용 `client_max_body_size 10m`, SELinux `httpd_can_network_connect` 켬).
- 백엔드 서버(Oracle Cloud ARM): 기존 서비스와 공유하는 nginx가 `/cat/` 경로를 서버 컨테이너(8088)로 넘긴다.
  서버는 `server.forward-headers-strategy=framework`로 프록시 뒤 URL을 만든다.
- 앱과 관리자 웹 모두 웹 서버 도메인의 `/api`로 요청한다. 실제 백엔드 도메인·IP는 공개 저장소에 적지 않는다.
- `infra/docker-compose.yml`: DB(호스트 5455)·MinIO(9000/9001)·서버(8088) 컨테이너.
  데이터는 `/home/rocky/my_cat_project/{db,minio}`, 서버 jar는 `/home/rocky/my_cat_project/cat_server/app.jar`.
- 스키마는 자동 적재되지 않는다: `docker exec -i cat-my-town-db psql -U catmytown -d catmytown < 산출물/schema.sql`
