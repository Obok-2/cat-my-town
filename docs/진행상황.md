## app/ 현재 상태

- 화면: 스플래시·로그인·카메라·매칭결과·이름짓기·도감·고양이상세·레벨·프로필. Google Cloud OAuth의
  ID Token을 서버가 검증한 뒤 자체 JWT(7일, Refresh Token 없음)를 발급하며 앱은 SecureStore에 보관한다.
  Google 네이티브 로그인 때문에 Expo Go가 아닌 Development Build가 필요하다. 촬영 직후 사진은
  `expo-image-manipulator`로 긴 변 최대 1280px·JPEG 품질 0.82로 줄여 `/app/camera/analyze`에 전송하며,
  `NOT_CAT`·`NEW_CAT`·`EXISTING_CAT` 결과 화면까지 서버와 연결됐다. 카메라 하단의 최근 7일 고양이 수도
  `/app/camera/week-count`로 조회한다. 나머지 데이터는 로컬(AsyncStorage) 목데이터다.
- 서버 호출은 `src/api/`의 기능별 모듈에서 axios + async/await로 단순하게 처리한다. 카메라 분석 요청은
  `cameraApi.js`, 신규 고양이 등록과 기존 고양이 목격 기록 요청은 `catApi.js`가 axios 응답을 그대로 반환하고 화면이 필요한 데이터를 꺼내 쓴다.
- 서버가 일치율 40% 이상 후보를 최대 3명 내려주며 앱은 이를 표시한다. 레벨 5단계(`src/data/levels.js`):
  1·5·12·16·30마리. README의 레벨 4단계·매칭 후보 1개 설명은 이와 어긋나 있음(README 미갱신).
- 고양이 상세 지도: **카카오 지도 JS SDK로 실제 지도 연동됨**(`KakaoMapView.js`/`.web.js`/`kakaoMapDraw.js`).
  좌표나 키가 없거나 로딩 실패하면 격자 자리표시자로 자동 전환. 키·설정은 `AGENTS.md`「지도」 참고.
  촬영 시 위치 권한이 허용되면 실제 GPS 좌표를 신규·기존 목격 기록에 함께 저장한다. 실기기 동작은 아직 확인하지 않았다.
- 실기기·에뮬레이터에서는 아직 아무것도 확인 안 됨(카메라 확대 배율 대략값, 손전등, 지도 WebView 등 전부 웹/헤드리스 브라우저까지만 검증).
- Expo 기본 앱 아이콘을 프로젝트 전용 고양이·위치 핀 마크로 교체했고, 런처·Android adaptive/monochrome·스플래시·favicon 자산을 갖췄다.
  화면 안의 문자 기호도 Ionicons로 통일했으며 라이선스 고지는 `app/THIRD_PARTY_NOTICES.md`에 둔다. 신규 등록 성공 시
  등록 성공 시 Capture·이름 짓기 모달을 `Completion` 일반 화면으로 교체한다. 완료 화면은 레벨업·신규 고양이·기존
  고양이 목격 기록 세 상태에 따라 문구·버튼·전용 고양이 일러스트를 구분하며, 모든 버튼은 도감(`/collection`)으로 이동한다.

## server/ 현재 상태

- Spring Boot 3.5, **JDK 17+ 필요**(로컬 `JAVA_HOME`은 11 — VS Code Java 확장에 딸린 JDK 21로 우회 가능,
  `C:\Users\Admin\.vscode\extensions\redhat.java-*\jre\21.*\bin\java.exe`).
- 구현된 API: `/app/collection/{count,cats}`(도감), `/app/level/count`(레벨), `/app/cat/{detail,markers,sightings}`(고양이 상세),
  `/app/camera/week-count`(최근 7일 목격 횟수·서로 다른 고양이 수),
  `/app/camera/analyze`(DJL 고양이 판별 + Voyage AI/pgvector 기존 개체 후보 최대 3마리),
  `/app/cat/register`(신규 고양이·첫 목격·태그 등록, MinIO 사진 저장, 목격 임베딩·레벨 계산),
  `/app/cat/sighting`(기존 고양이 목격·사진 등록), `/app/photo`(`catId`로 사용자 소유 고양이의 첫 목격 사진 조회). 촬영 분석 응답 상태는
  `NOT_CAT`·`NEW_CAT`·`EXISTING_CAT` 세 가지다. 동일 개체 비교에는 실행 환경의 `VOYAGE_API_KEY`가 필요하다.
  신규 등록과 기존 고양이 목격 등록은 분석 사진을 MinIO 저장용으로 다시 multipart로 받는 MVP 방식이다.
  분석 시 생성한 Voyage 임베딩은 `analysisId`로 서버 메모리에 30분간 보관하고 확정·등록 시 재사용하여 같은 사진으로 Voyage API를 두 번 호출하지 않는다.
  `/app/cat/sighting`은 선택한 고양이가 해당 사용자 소유인지 확인한 뒤 사진을 MinIO에 저장하고
  Voyage AI 임베딩과 목격 기록을 추가하며 레벨은 바꾸지 않는다. 매칭은 각 고양이의 목격 임베딩 중 유사도 상위 2개의 평균을 사용하고 고양이별로 후보 하나만 반환한다.
  코딩 규칙·URL 체계는 `AGENTS.md`「코딩 규칙 (Java)」 참고.
- Spring Security가 자체 HS256 JWT를 검증한다. `/app/auth/google`만 공개이며 나머지 앱 API는 Bearer 인증이 필요하다.
  Google ID Token의 서명·issuer·audience·만료를 검증하고 `sub`를 `users.google_uid`로 사용한다. Refresh Token은 사용하지 않으며
  JWT가 만료되면 Google 로그인을 다시 받는다. `infra/.env`는 Git에서 제외된다. `application.properties`는 추적 중이므로
  비밀값이 들어 있는 로컬 변경분은 커밋에서 제외했다. 다른 환경에서는 `GOOGLE_CLIENT_ID`·`JWT_SECRET`을 환경변수로 제공해야 한다.
- 로컬 앱·웹 개발용 CORS는 `WebConfig`에서 전체 경로에 공통 적용한다.
- 앱 카메라 분석과 신규 고양이 등록, 기존 고양이 목격 등록 화면에 연결됨. 도감(`/collection`) 화면은
  `/app/collection/cats`·`/app/collection/count`·`/app/photo` API로 목록, 레벨 진행률, 대표 사진을 조회하며 화면 재진입과
  당겨서 새로고침을 지원한다. 고양이 상세 화면은 `/app/cat/detail`·`/app/cat/markers`·`/app/cat/sightings`를 사용하며
  목격 타임라인을 10건씩 추가 조회한다. 모든 조회 API의 `photoUrl`은 앱에서 바로 표시할 수 있는 `/app/photo?catId=` 또는
  `/app/photo?sightingId=`의 완전한 URL이며, 사진 API는 MinIO 객체를 `inline` 이미지 리소스로 내려준다.
  기존 고양이 후보 선택 뒤에는 목격 기록 작성 화면에서
  메모와 특징 태그(최대 5개)를 입력한 후 저장한다. 촬영 시 `expo-location`으로 위치 권한을 요청하고, 허용된 경우 신규·기존 목격 모두
  위도·경도를 `sightings`에 저장한다. 특징 태그도 고양이 공통 테이블이 아니라 각 `sightings.tags`의 쉼표 구분 값으로 저장한다.
  레벨 화면은 `/app/level/count`를 탭 재진입과 당겨서 새로고침 때 호출하고, 받은 고양이 수를 앱의 등급표로 계산한다.
  등급표는 달성한 등급을 초록색, 현재 등급을 주황색 테두리·그림자, 미달성 등급을 중립색으로 구분한다.
  나머지 앱 데이터는 아직 로컬 목데이터.

## web/ 현재 상태

- React + Vite(JS), 로그인·대시보드만 실제 동작(목데이터). 나머지 메뉴는 "작업 중" 자리표시자 화면.
- 서버 API에 연결 안 됨.
- 앱과 같은 고양이 마크를 favicon·로그인 화면·관리자 사이드바 브랜드에 적용함.
- 실행: `cd web && npm install && npm run dev`

## infra/ 현재 상태

- 로컬 DB는 호스트 포트 **5455**(기본 PostgreSQL과 충돌 회피), MinIO는 API 9000·콘솔 9001. 실제 DB명·계정명·비밀번호와
  MinIO 관리자 이름·비밀번호는 Git에서 제외된 `infra/.env`에 두고, 키 이름만 `infra/.env.example`로 공유한다.
- 스키마는 자동 적재 안 됨 — 직접 실행: `docker exec -i cat-my-town-db psql -U catmytown -d catmytown < 산출물/schema.sql`

## 산출물/ 현재 상태

- `앱_REST_API_인터페이스_정의서.md` v0.3: 구현된 API만 최신 주소·응답 형태 반영, 나머지는 예전 초안 그대로.
