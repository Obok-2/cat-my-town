## 폴더 구조 (현재 상태)

```
app/     React Native(Expo, JS) 앱 — 화면 스캐폴딩 완료(로컬 목데이터 기반), 백엔드 미연동
server/  Spring Boot 3.5 + MyBatis 백엔드 — 프로젝트 스캐폴딩만 완료(컨트롤러·서비스·DAO 없음)
web/     관리자 웹 (React + Vite, JS) — 로그인·대시보드 구현 완료(목데이터), 나머지 메뉴는 "작업 중" 화면
infra/   인프라 설정(Docker Compose 등) — 지금은 로컬 개발용 DB(PostgreSQL + pgvector)만
design/  화면 목업(PDF)
doc/     기획 문서 — 비어있음
docs/    이 진행상황 문서
```

## 작업 기록 (최신순)

### 2026-09-21 (백엔드 `server/` 프로젝트 스캐폴딩)
- Spring Boot **3.5.16**(3.x 마지막 라인의 최신 패치) · Gradle 8.14.3(wrapper 포함, Groovy DSL) · Java 17 ·
  그룹 `com.catmytown`, 패키지 `com.catmytown.server`. 사용자가 컨트롤러·서비스·DAO는 따로 요청하기로 해서
  `ServerApplication` + `contextLoads` 테스트만 있음
- 의존성: web, validation, actuator(health만 노출), **MyBatis starter 3.0.5**(Boot 3.x용 — 4.x는 Boot 4 전용),
  PostgreSQL 드라이버, Lombok, devtools
- `application.properties`(yml 아님 — 사용자 요청으로 properties 사용): DB 접속 정보는 `DB_URL`/`DB_USERNAME`/`DB_PASSWORD` 환경변수(기본값은 docker-compose와 동일),
  `SERVER_PORT`(기본 8080), MyBatis 매퍼 위치 `classpath:mapper/**/*.xml`(`resources/mapper/`), snake→camel 매핑, 타임존 Asia/Seoul
- `infra/docker-compose.yml`: 로컬 개발용 `pgvector/pgvector:pg16` (DB/유저/비번 기본값 `catmytown`).
  처음엔 `server/` 안에 뒀다가, 인프라 파일은 코드와 분리해 관리하려고 저장소 루트의 `infra/`로 이동함.
  실행은 `cd infra && docker compose up -d`, 프로젝트명은 `cat-my-town`으로 고정. `infra/.env`(gitignore)로 DB 계정 덮어쓰기 가능
- 아직 안 넣은 것: Spring Security·Firebase 인증(넣으면 전 엔드포인트가 잠겨서 인증 방식 결정 후 추가), 스키마/마이그레이션 도구,
  pgvector 확장 활성화·테이블 DDL, Dockerfile, 이미지 저장소(MinIO)
- ⚠️ **로컬 JDK가 11이라 그대로는 빌드 불가** — Boot 3.x는 JDK 17+ 필요. 이 세션에서는 시스템 설정을 건드리지 않고
  포터블 JDK 17을 임시 폴더에 받아 검증만 함. 실제로 쓰려면 JDK 17 또는 21 설치 후 `JAVA_HOME` 변경 필요
- 검증(JDK 17): `./gradlew build` 성공(테스트 포함, 클래스 major version 61), `bootRun` 1.7초에 기동,
  `/actuator/health`는 DB가 없어 DOWN(503) — DB 기동 후 UP 확인은 못 함(Docker Desktop이 꺼져 있었음)
- 참고: 앱 개발 서버(Expo Metro)가 8081을 쓰므로 `SERVER_PORT=8081`은 충돌. 기본 8080 사용
- README의 프로젝트 구조는 백엔드를 `back/`으로 적고 있으나 실제 폴더는 `server/` (README 미수정)
- 아직 커밋 안 함 — 사용자가 직접 커밋·push 하기 전까지 대기 (AGENTS.md 절대 규칙 1조)
