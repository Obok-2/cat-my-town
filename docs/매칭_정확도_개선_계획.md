# 매칭 정확도 개선 계획

같은 고양이를 다시 찍었을 때 올바른 고양이가 후보로 나오고, 다른 고양이는 후보에 오르지 않도록
동일 개체 판별 정확도를 높이기 위한 계획이다. 앱·관리자 웹·API 응답 형식은 바꾸지 않는다.

| 차수 | 목표 | 상태 |
|---|---|---|
| **1차 완성** | 촬영 → 판별 → 매칭 → 등록 → 도감까지 전체 흐름을 실제로 동작하게 만들기 | ✅ 완료 (2026.09.21 ~ 09.24) |
| **2차 성능 향상** | 1차에서 드러난 오매칭(배경·비슷한 무늬·자세 차이)을 줄이기 | 🔄 진행 중 |

---

# 1차 완성

## 1-1. 구조

```
촬영 사진(전체) → DJL ResNet-18(고양이 판별) → Voyage AI 임베딩(사진 전체) → pgvector 검색 → 후보
```

- 판별: ImageNet 고양이 계열 클래스 확률 합 0.15 이상이면 고양이
- 임베딩: Voyage `voyage-multimodal-3.5`(1024차원, 유료 API)
- 매칭: 고양이별 목격 사진 중 유사도 상위 2장 평균 → 보정 일치율(0.75~0.92 → 0~100%) 40% 이상, 최대 3마리
- 최종 확인은 사용자("이 고양이예요" / "새로운 고양이예요")

## 1-2. 실제로 써 보고 드러난 문제

- **배경 영향:** 사진 전체를 임베딩해서, 배경이 비슷하면 다른 고양이도 유사도가 높게 나온다.
- **비슷한 무늬:** 흰색+회색 무늬 고양이와 털이 긴 고등어·삼색 고양이가 일치율 46~52%로 후보에 올랐다(기준 40% 초과).
  범용 임베딩(Voyage)은 "무슨 사진인지"(종류·상황)를 잘 보도록 학습돼, 둘 다 "무늬 있는 고양이"로 가깝게 만든다.
- **자세 차이:** 앉은 모습과 걷는 모습처럼 자세가 다르면 같은 고양이도 유사도가 떨어진다.
- **판별 누락:** ResNet-18은 고양이가 작게 찍히거나 가려지면 놓치기 쉽다.

# 2차 성능 향상

## 2-0. 목표 구조와 모델 선택

```
앱 → Spring 서버 ──사진──→ vision 서버(FastAPI, 컨테이너 1개)
                            ├ RT-DETR v2 : 고양이 찾기 + 네모로 자르기
                            └ DINOv2     : 잘라낸 고양이 → 임베딩
                  ←── { isCat, confidence, box, image, embedding }
     Spring → pgvector 검색(+ 위치 가중치) → 후보 → 사용자가 최종 확인
```

- 모델은 **이미 학습된 공개 모델을 그대로 가져다 쓴다**(처음부터 학습·파인튜닝하지 않음).
- **상업 사용이 가능한 라이선스(Apache 2.0)만 고른다.** Hugging Face 모델 카드의 라이선스 표시로 확인했다(법률 검토는 아님).
  YOLO(AGPL-3.0)와 MegaDescriptor(CC BY-NC 4.0, 비상업)는 이 기준 때문에 제외했다.
- **Voyage AI 호출이 없어진다.** 사진 한 번 보내면 vision 서버 안에서 "자르기 → 임베딩"을 이어서 처리한다.
- **임베딩 모델은 서버를 따로 두지 않고 vision 서버 안에 같이 둔다.** 둘 다 Python·PyTorch라 같은 환경에 들어가고,
  사진을 한 번만 주고받으며, 관리할 컨테이너가 늘지 않는다. 사용량이 크게 늘면 그때 나눈다.
- 원본 사진은 지금처럼 MinIO에 저장하고 앱에는 원본을 보여준다. **잘라낸 이미지는 저장하지 않는다.**
- 배경은 지우지 않고 **박스로만 자른다.** 배경 제거(마스크)가 정말 필요한지는 테스트 세트로 비교해서 정한다(2-7).

| 모델 | 하는 일 | 비유 | 가격·라이선스 |
|---|---|---|---|
| **RT-DETR v2** `PekingU/rtdetr_v2_r18vd` (채택) | 사진에서 고양이 **위치를 찾고**(네모 좌표), 고양이 여부 판별. COCO로 학습 | 고양이를 찾아 동그라미 치는 사람 | 무료 · Apache 2.0 |
| **DINOv2** `facebook/dinov2-small` (채택) | 잘라낸 고양이를 **숫자 목록(임베딩, 384개)**으로 바꿈. 무늬·질감 같은 세부 모양에 강함 | 세부 모양을 잘 보는 카드 작성자 | 무료 · Apache 2.0 |
| DINOv2-base, RT-DETR r50 (예비) | 더 크고 정확한 버전(임베딩 768개). CPU에서 느려짐 | | Apache 2.0 |
| ConvNeXt-Base, EfficientNetV2-M (timm, 비교용) | ImageNet "종류 분류"로 학습된 모델의 임베딩. 개체 구분은 학습한 적 없음 | | Apache 2.0 (Hugging Face 표시) |
| Voyage (제거 예정, 비교 기준선) | 임베딩. 사진↔글 짝을 학습해 "무슨 사진인지"에 강함 | 말로 설명하는 카드 작성자 | 유료 API · 사진이 외부로 전송됨 |
| MegaDescriptor (제외) | 동물 개체 구분에 학습된 임베딩. 상한선 참고용으로만 로컬에서 비교 | 개체 구분을 공부한 카드 작성자 | **CC BY-NC 4.0, 비상업이라 서비스에 사용 불가** |

**한계:** DINOv2는 개체 구분에 학습된 모델이 아니라 그대로는 비슷한 무늬의 다른 고양이를 헷갈릴 수 있다(동물 개체 식별의 zero-shot은
약하다는 연구가 있다). 위치 가중치(④)·촬영 안내(②)·사용자 최종 확인으로 보완하고, 그래도 부족하면 사용자가 "이 고양이예요"를 누른
데이터로 DINOv2를 미세조정하는 것을 다음 방법으로 본다(라이선스상 가능).

## 2-1. 단계 요약

| 단계 | 내용 | 해결하는 문제 | 상태 |
|---|---|---|---|
| ① 고양이만 잘라 임베딩 | vision 서버(RT-DETR)로 고양이 네모만 잘라 임베딩 | 배경 영향, 판별 누락 | 🔄 vision 서버 로컬 실행 확인(사진 1장), Spring 연결 전 |
| ② 촬영 안내 | 카메라 화면에서 얼굴 정면이 보이게 찍도록 안내 | 자세 차이 | 🔄 안내선 구현 완료, 효과 측정 전 |
| ③ 임베딩 교체 | Voyage → DINOv2 (vision 서버에 이미 포함, 비교 후 결정) | 비슷한 무늬, 자세 차이 | ⏳ |
| ④ 위치 가중치 | 가까운 곳에서 본 고양이일수록 점수 가산 | 비슷한 무늬 | ⏳ |
| ⑤ 자세 추가 대응 | 얼굴만 비교, 무늬 특징점 비교 등 | 자세 차이 | 필요할 때 |

각 단계는 **같은 테스트 세트로 측정(2-7)**해서 실제로 좋아진 것만 적용한다.

## 2-2. ① 고양이만 잘라 임베딩

### vision 서버 (`vision/`, 로컬 실행 확인 · 사진 1장)
- `POST /analyze`: 사진 1장을 받아 결과를 돌려준다.
  - 고양이 없음: `{ "isCat": false, "label": "...", "confidence": 0.0 }`
  - 고양이 있음: `{ "isCat": true, "confidence": 0.93, "box": { "x": 0.21, "y": 0.34, "w": 0.40, "h": 0.52 }, "image": "<잘라낸 JPEG, base64>", "embedding": [384개] }`
  - 고양이가 여러 마리면 **확률 × 면적**이 가장 큰 한 마리를 고른다.
- 탐지 모델 `PekingU/rtdetr_v2_r18vd`, 임베딩 모델 `facebook/dinov2-small`(환경변수로 교체). 서버 시작 시 한 번 불러 둔다.
- 고양이 네모에 여백 8%를 두고 자른 뒤(배경은 그대로), 비율을 유지한 채 회색으로 정사각형을 만들어 DINOv2에 넣고 CLS 벡터를 길이 1로 정규화한다.
- Dockerfile: ARM64·x86 CPU.
- **이전(YOLO11-seg) 로컬 확인 결과 — 참고**
  - 삼색 고양이(흰 벽·시멘트 바닥): 판별 90.5%, 배경이 깔끔하게 제거됨, 처리 약 140ms
  - 치즈 고양이(베이지 방석 위): 판별 41.2%로 낮고, 털색과 비슷한 방석 일부가 마스크에 같이 남음
- **RT-DETR + DINOv2 로컬 확인 결과(Windows, CPU, 삼색 노르웨이숲 1장, 긴 변 1280px JPEG)**
  - 판별 96.8%, 박스가 꼬리·발까지 고양이 전체를 감쌈, 한 장 약 0.4초(모델을 불러 둔 뒤), 임베딩 384개(길이 1)
  - 사진이 1장뿐이라 정확도 평가가 아니다. 다른 고양이·어려운 사진(작게 찍힘, 가려짐, 치즈 고양이 등)과 ARM 서버 속도는 테스트 세트로 확인한다.

### 남은 작업
- **인프라:** `infra/docker-compose.yml`에 `vision` 컨테이너 추가. 외부 포트는 열지 않고 Spring만 `http://vision:8000`으로 호출.
  모델 가중치는 호스트 폴더에 캐시.
- **Spring 서버**

  | 파일 | 변경 |
  |---|---|
  | `CatImageClassifier.java` (DJL) | 삭제 → `VisionClient.java`(RestClient로 vision 서버에 multipart 전송)로 대체 |
  | `CameraService.java` | 판별 결과를 VisionClient에서 받고, 잘라낸 이미지를 Voyage로 보냄(비교 기간). `NOT_CAT` 기준을 RT-DETR 확률로 변경 |
  | `CatService.java` | 등록·목격 저장 시 박스 좌표·확률을 함께 저장 |
  | `AnalysisEmbeddingStore.java` | 임베딩과 함께 박스 좌표·확률도 30분 보관 |
  | `build.gradle` | DJL 의존성 삭제(jar 경량화, Windows 로컬 실행 시 DLL 차단 문제도 해소) |
  | `application.properties` | `vision.url=http://vision:8000` 추가 |

  vision 서버가 꺼져 있으면 `BusinessException(503)`으로 바꿔 기존 에러 형식을 유지한다(내부 주소는 앱에 노출하지 않음).
- **DB (`sightings`)**

  | 컬럼 | 타입 | 뜻 |
  |---|---|---|
  | `cat_box_x`, `cat_box_y`, `cat_box_w`, `cat_box_h` | NUMERIC(5, 4) | 고양이 위치 네모(사진 크기 대비 0~1 비율) |
  | `cat_confidence` | NUMERIC(5, 4) | 탐지 모델이 고양이라고 판단한 확률 |

  한 사진에 고양이가 여러 마리일 때 나중에 다시 계산해도 같은 고양이를 고르기 위해, 그리고 디버깅·기준값 튜닝용.
  잘라낸 이미지 자체는 저장하지 않는다. `schema.sql`과 ERD를 함께 고친다.
- **기존 데이터:** MinIO 원본 → vision → 임베딩·박스 좌표를 한 번 다시 만든다. 원본 사진은 절대 지우지 않는다.

## 2-3. ② 촬영 안내

다른 개체 식별 서비스(펫나우 등)는 **찍는 자세 자체를 비슷하게 만드는 것**으로 자세 차이를 가장 크게 줄인다.
- 카메라 화면에 앉은 고양이(정면 얼굴 + 몸통) 모양 틀을 띄우고 "고양이 전체가 선 안에, 얼굴은 정면으로 맞춰 주세요"로 안내한다. 얼굴만 크게 잡으면 화면이 얼굴로 가득 차서 몸통 무늬가 안 보이므로 몸통까지 함께 넣었다.
  **구현됨**: `app/src/components/CatGuide.js`(SVG 앉은 고양이 윤곽: 머리·눈·코·수염·몸통·앞다리·꼬리). 화면에만 보이고 사진에는 찍히지 않으며, 예전 네 모서리 프레임을 대체했다.
- 길고양이는 가만히 있지 않으므로 **강제하지 않고 안내만** 한다.
- 앱 화면만 바꾸면 되는 가장 쉬운 개선이다. 실제로 정확도가 좋아지는지는 안내선이 있을 때와 없을 때를 테스트 세트(2-7)로 비교해서 확인한다.

## 2-4. ③ 임베딩 교체 (Voyage → DINOv2)

- **vision 서버:** DINOv2를 RT-DETR와 함께 불러 두고(Hugging Face에서 가져옴, 가중치 캐시) `/analyze` 응답의 `embedding`으로 내려준다(코드 작성 완료).
  잘라낸 이미지(`image`)는 Voyage와 비교하는 기간과 디버깅용으로 함께 내려준다.
- **Spring:** `VoyageImageEmbeddingClient.java` 삭제 → vision 응답의 `embedding`을 사용. `camera.voyage.*` 설정 삭제.
- **DB — 임베딩 값이 완전히 달라진다.** 모델마다 숫자 개수(차원)와 숫자의 뜻이 달라서, Voyage 값과 DINOv2 값은 서로 비교할 수 없다
  (Voyage 1024개, DINOv2 small 384개·base 768개). 전환 기간에는 새 컬럼을 두고 나란히 저장한다.
  ```
  sightings.embedding      VECTOR(1024)    -- Voyage (기존)
  sightings.embedding_v2   VECTOR(새 차원)  -- DINOv2 (추가, HNSW 인덱스 별도)
  ```
  같은 사진으로 두 모델을 바로 비교하고, 새 모델이 나으면 검색을 `embedding_v2`로 바꾼 뒤 기존 컬럼을 지운다.
  나쁘면 새 컬럼만 지워 되돌린다. 기존 목격 사진은 MinIO 원본으로 `embedding_v2`를 한 번 다시 만든다.
- **기준값:** 새 모델은 유사도 숫자 범위가 달라서 보정 기준값(0.75 / 0.92 / 40%)을 반드시 다시 정한다.
- **문서·안내:** 개인정보 안내의 "사진이 Voyage AI로 전송된다" 문구 삭제, README 기술 스택·구성도 수정.
- **진행 순서:** 테스트 세트 준비 → vision 서버 실행·처리 시간 측정 → Voyage vs DINOv2(+ConvNeXt·EfficientNetV2 등 비교 후보) 비교 → 더 나은 쪽으로 교체·재변환·기준값 조정

## 2-5. ④ 위치 가중치

- 길고양이는 활동 반경이 좁다. 새 사진 위치와 기존 목격 위치가 가까울수록 점수를 더하고,
  멀리 떨어진 고양이는 감점·제외한다(모든 목격 기록에 좌표가 있으므로 SQL 계산만으로 가능).
- 측정 결과에 따라 후보 기준(40%)을 올려 애매한 후보를 줄이는 것도 함께 검토한다.

## 2-6. ⑤ 자세 추가 대응 (②~④로 부족할 때)

| 방법 | 설명 | 참고 사례 |
|---|---|---|
| 여러 자세 모으기 | 한 개체를 여러 각도로 쌓고 가장 비슷한 사진과 비교 | **이미 적용**(상위 2장 평균). 목격이 쌓일수록 좋아짐 |
| 얼굴만 비교 | 몸은 자세에 따라 크게 바뀌지만 얼굴은 비교적 일정. 몸을 찾은 뒤 얼굴을 한 번 더 찾아 비교 | 펫나우(고양이 얼굴), Petco Love Lost |
| 무늬 특징점 비교 | 무늬의 점·줄무늬 끝 같은 특징점을 직접 맞춰 봄. 자세가 달라도 일부 맞출 수 있음 | Wildbook(얼룩말·고래·표범) |

## 2-7. 측정 방법

- **테스트 세트:** 고양이 10~20마리 × 각 3~5장(각도·장소를 일부러 다르게). 직접 찍은 사진 또는 자유 이용 가능한 사진만 쓴다.
- **지표**
  - Top-1 정확도: 같은 고양이가 1순위 후보로 나온 비율
  - Top-3 정확도: 같은 고양이가 후보 3마리 안에 든 비율
  - 오매칭률: 다른 고양이가 기준(40%)을 넘어 후보에 오른 비율
  - 판별 실패율: 고양이 사진인데 `NOT_CAT`이 나온 비율
- **비교:** 1차(지금) → ① → ③ → ④ 순서로 같은 테스트 세트에서 측정해 표로 남긴다.
- 각 단계마다 유사도 분포를 보고 보정 기준값(`lower-bound`·`upper-bound`·`threshold`)을 다시 정한다.

## 2-8. 주의할 점

- **라이선스:** 채택한 RT-DETR v2·DINOv2는 Hugging Face 모델 카드에 Apache 2.0으로 표시돼 있다(법률 검토 아님). 학습 데이터(COCO·ImageNet)의 조건은
  별도이니 상업 출시 전에 다시 확인한다. Ultralytics YOLO(AGPL-3.0)와 MegaDescriptor(CC BY-NC 4.0)는 서비스에 넣지 않는다.
  모델을 바꿀 때는 코드 저장소와 가중치 모델 카드의 라이선스를 각각 확인한다.
- **속도·메모리:** ARM CPU(2 OCPU·12GB)에서 RT-DETR r18 + DINOv2 small은 가벼운 편으로 예상하지만 실제 측정 전이다.
  base·r50으로 올리면 느려지므로 테스트 세트에서 정확도와 처리 시간을 같이 본다.
- **기대치:** 배경 영향은 확실히 줄고, 비슷한 무늬·자세 차이는 줄어들 가능성이 크지만 측정으로 확인해야 한다.
  무늬가 거의 같은 고양이는 전용 모델로도 완벽히 구분하기 어려우므로 "AI는 후보 제안, 확정은 사용자" 구조는 유지한다.
